# Operator guide

1. Open **Add Input** and add a camera, clip, graphic or network source. Click a card to prepare it in **Preview**. Use **Cut**, a transition or the T-bar to send it to **Program**.
2. Configure layers, positioning, picture and sound in **Input Settings**. Assign an input to one of the eight overlays when it should appear above the video.
3. Choose the source for each output in **Settings → Outputs / NDI / OMT / SRT**. Set the corresponding destination or hardware connector before enabling it.
4. Save the show as a `.livemix` project preset. To open an older XML preset in Windows, select **All files** in the Open dialog. Use **Save As** to save it with the new extension. Reopening it shows an import report with unsupported inputs and missing asset references. Keep the media files accessible from the machine that opens the show.

Enable **Settings → Options → Start External Output** to open the local External 1 window when LiveMix starts. The window uses the source configured for Output 1.

**Last** restores the automatic recovery preset in the LiveMix storage directory. LiveMix writes this copy roughly every 60 seconds and before **New** or a normal exit. The untouched startup demo and empty projects are skipped. Use **Save As** after restoring to create an ordinary project file.

## Display and source selection

In DeckLink **Input Settings → General**, select 2, 8 or 16 embedded audio channels. In **External Output**, enable **16 channels (Master, A–G)** to send eight stereo pairs in that order. Desktop Video hardware and profile support are required. In **Audio Settings → Dynamics**, **Reverb Tail Reduction** attenuates decaying room sound between phrases.

Enable **Audio Settings → Dynamics → Noise Suppression** for CPU-based RNNoise processing. Direct channel routes still use capture audio before input effects. On Windows, DeckLink capture tries 16, eight and then two embedded channels. The direct channel matrix exposes the available capture channels. For 10-bit DeckLink playback, enable **External Output → 10-bit YUV (v210)** with a compatible video mode. This converts the current 8-bit Program image to the 10-bit output format.

Use **Add Input → Mix** to create a reusable layered composition. Assign its sources in **Input Settings → Layers**. Right-click the Mix card header to choose its Preview and use **Mix Cut** or **Mix Fade** to swap the first layer. Enable **Tally Passthrough** in General to show Program or Preview tally on the active layers and in MIDI feedback.

Use **Input Audio Settings → Bus Mixer** to assign Master or buses A–G. In **MultiCorder Setup → Audio source**, choose the original source, a single bus or a combined bus preset. The chosen mix is written as stereo to each MultiCorder recording.

In **Input Settings → General**, set **GO action** to a shortcut command such as `Preview @input` or `FadeDirect @input 500`. Empty uses Quick Play. The button tooltip shows the configured action.

In **Streaming Settings**, choose **Custom SRT Server** and enter the provider's full SRT URL with its query options. Each SRT stream uses its own encoder and the selected streaming size and bitrate. Local SRT feeds can still be configured in **Outputs / NDI / OMT / SRT**. There are eight independently configurable output routes, including External Renderer on compatible DeckLink devices.

Input **Audio Settings → General** shows stereo meters before and after the input fader. **Meters Pre-Fader** selects the reading shown on the mixer strip, and **Visible in Mixer** controls whether the strip is shown. **Right trim** adjusts the right channel independently. Name and save custom stereo matrices in **Channel Matrix**. Those presets travel with the input in the project.

Supported audio devices and NDI/OMT receivers expose up to eight capture channels. Use **Channel Matrix → Additional capture channels** to fold channels 3–8 into left and right before the stereo processing stage. **Dynamics** offers software automatic gain control and low/high thresholds with adjustable attack. These settings are stored with the input.

In **Channel Matrix**, select **Master**, **A**, **B** or **Headphones** and enable **Direct channel routing** to map up to eight original capture channels to that destination's stereo pair. Direct routes use samples before input DSP. Master, A and B still use the input's bus assignment and fader. A Headphones route can monitor an input independently of the bus selection. Sources without multichannel capture support use their ordinary stereo path.

In an input's **Audio Settings**, use **Channel Mixer** to select stereo, duplicate one channel, swap channels or sum to mono. **Channel Matrix** applies a 2 × 2 gain matrix after that selection. Leave Channel Mixer on Stereo to route the original left and right signals independently. **Bus Mixer** assigns the input to Master, A and B. The EQ, gate and compressor can be bypassed without resetting their parameters.

In **Recording Setup**, choose the recording folder and click **Test Write Speed**. LiveMix writes a temporary 512 MiB file, synchronizes it to disk and reports the average sequential write speed in MB/s. The test removes the temporary file on completion or cancellation. For profiles with a configured video bitrate, it shows the combined target for the enabled recordings. Actual recording rates also depend on the codec, audio and container.

In **Input Settings → Effects**, use **Blur** and load an **Alpha mask** for supported video and image inputs. Transparent masks use their alpha channel, and opaque masks use brightness. Both settings are saved with the project. These effects process frames in system memory.

Under **External Output**, each DeckLink tab can select Master or a bus from A–G for embedded stereo audio and apply up to 1,000 ms of audio delay.

Under **Outputs / NDI / OMT / SRT → Advanced Settings**, use **On Top** and **Hide Cursor** to control the local External windows.

For an external graphics keyer, choose a DeckLink playback device and a supported format, enable **Alpha Channel → Key + Fill (Graphics Only)**, then start **External Renderer**. Put graphics on Program overlay channels. This mode sends those overlays over a transparent background and uses the hardware to generate the two SDI signals. Match the format on the switcher and use the key inputs and connector mapping for the selected Desktop Video profile. Graphics Only sends video without embedded audio.

NDI and OMT inputs use sender timestamps, when available, to schedule audio and video on the same local clock with a 60 ms initial buffer. Video Delay uses the chosen delay for both the picture and the source audio. Use the delay input's mixer strip to route or mute its audio.

**Settings → About** shows the FFmpeg executable selected by LiveMix. With hardware encoding enabled, FFmpeg streaming and H.264/HEVC recordings test the encoder at the selected output size and frame rate. If no hardware encoder passes, LiveMix selects software and reports the fallback in the stream log or recording encoder status.

**Settings → Performance → Preview Skip** controls how often off-air input cards refresh. Video frames in system memory used only by those cards are uploaded at card size, with the latest full-size frame retained for immediate promotion to Preview or Program.

In **Settings → Display**, set the theme and the Preview and Output colors. The colors also apply to the matching input and MultiView title bars. Set the monitor, source and overlay option separately for **Fullscreen 1** and **Fullscreen 2**. Open them from the top toolbar. Active outputs use separate monitors. Click the Production Clock under the overlay buttons to pause or resume, and right-click to reset.

Use **Add Input → Audio** for an audio-only file. **Recent media** remembers the last successfully added video, image, audio files and photo folders. In **Settings → Performance**, turn NDI/OMT thumbnails on or off. The browser requests a single frame per source and keeps source selection available while previews load.

Use **Add Input → Web Browser** for an HTTP or HTTPS page. Under **Input Settings → General**, change or reopen its URL and enable **Transparent** to preserve alpha from a page with a transparent background. Chromium renders at 1280×720. LiveMix requests up to 15 pictures per second for on-air or monitored sources and two per second for other cards. Open the input's **Preview** window and click the picture to focus it. Mouse, scrolling, text, paste and keyboard navigation are sent to the page. Top-level Web Audio and eligible HTML media elements feed the input's stereo mixer channel. Protected media, cross-origin media that Chromium blocks from capture and audio from embedded frames can be silent.

On camera, video, image and other picture inputs, use **Input Settings → Colour Correction → 3D LUT** to browse for a .cube or tiled PNG LUT. Supported cubes have 2–65 samples per axis. For PNG, use a strip or grid of square blue slices with red across each tile and green down it, such as a 512×512 8×8 grid. The project keeps the LUT path, so keep the file accessible when moving a preset. Use **Colour Key → Luma Key** to remove dark pixels, adjust **Threshold** and **Softness**, or enable **Remove bright pixels** to invert the key. Use a keyed input as an overlay or layer to reveal the background.

Use **Add Input → PowerPoint** to open a presentation. Wait for conversion, then use the previous and next buttons on the input card or in **Input Settings → General**. Save the original deck alongside the project. Slides render as stills.

Use **Add Input → Virtual Set** and open **Input Settings → Layers**. Assign a backdrop to layer 1, presenter inputs to layers 2 and 3 and a desk or foreground to layer 4. Enable chroma key on the presenter inputs when needed. Choose **Wide**, **Left** or **Right** under **General → Camera**.

In **Streaming Settings**, choose one of five slots, then select its source, resolution, bitrate and codec. Destinations with matching source, audio, resolution, bitrate and codec share one RTMP encoder. Starting or stopping a member can restart that group. HEVC over RTMP/RTMPS requires a compatible FFmpeg build and receiver. [YouTube Live encoder settings](https://support.google.com/youtube/answer/2853702)

## Audio, recording and streaming

Add a microphone or interface with **Add Input → Audio Input**. In **Audio Mixer**, use **HP** and the adjacent selector to monitor Master, A or B through the system output. Drag the round knob vertically to change headphone volume. Double-click to reset it to 100%. Use **i** on the Master strip to inspect Audio Engine statistics. Click **OUTPUTS** or **INPUTS** to collapse a group, and use a channel gear to open its audio settings. Right-click the mixer title to make the input strips follow the selected input category. **Input Settings → Audio → Audio Settings** opens the same per-input dialog as the mixer gear. It provides channel selection, gain and delay under General, with separate pages for EQ, compression and noise gate. Input and Master faders and the headphone knob use an audio taper: 100 is unity gain (0 dB), 75 is about −10 dB and 50 is about −24 dB. Hover a fader to see its gain and dB. On each input strip, use **M**, **A** and **B** to assign buses and the speaker button to mute. **S** isolates the selected inputs in headphone monitoring. Right-click **S** for pre-fader Solo, which ignores the input fader and mute. The automatic mixing button follows Program with a crossfade on timed transitions and preserves mute and bus assignments. Each input card with audio has a stereo meter. In **Settings → Display → MultiView**, enable **Program audio meter** or **Input audio meters** for each layout. Program and MultiView routes use the Master mix. Preview and per-input routes take the corresponding input audio.

Use the Record gear to configure Recording 1 and Recording 2. Each slot has a video source, codec and **Audio track** toggle. Composed outputs record the stereo Program mix. MultiCorder uses the same codec choices and can record each selected source separately. Camera files use their source audio when available. Both recording slots share the destination folder and split interval.

| Container | Video profiles | Stereo audio |
| --- | --- | --- |
| MP4 and MKV | H.264, HEVC | AAC |
| AVI | MJPEG, MagicYUV | PCM |
| MPEG-2 TS and PS | MPEG-2 | MP2 |
| WMV | WMV8, WMV9 on Windows | WMA2 |
| MOV and MXF | ProRes 422 (MOV), DNxHR HQ | PCM |

Open the Stream gear for RTMP/RTMPS destinations. Each slot defaults to the **Master mix**, with **Selected video source** available for isolated audio. YouTube uses stereo AAC at 44.1 kHz and 128 kbps. Open **Streaming log** to inspect encoded video progress, input audio peak and sample counts, and FFmpeg messages. **Copy log** copies the recent lines with destination URLs and credentials removed. SRT output settings show the same diagnostics. Destinations with matching encoding and audio settings can share an encoder. Changing group membership restarts that encoder.

The Preview waveform, RGB parade and vectorscope use OpenGL when available. **Settings → Performance** reports the active scope path. Waveform and parade textures are 1200×256 and the vectorscope is 512×512. The LiveMix scopes sample the composed Preview at 640×360. On Windows, compatible D3D11 file playback applies chroma key and colour correction in OpenGL. Inputs supplying a Video Delay buffer still use system-memory pictures.

In **Settings → Decoders**, choose FFmpeg for specific file extensions or all video files on Windows. Other files first try Media Foundation, with FFmpeg as a fallback when it cannot deliver the first picture. macOS uses FFmpeg for video files. **BWDIF** and **YADIF** deinterlace frames marked as interlaced on the FFmpeg path. Changes apply the next time a video or playlist reader opens. See **Input Settings → General → Decoder** for the active path. FFmpeg and FFprobe must be available to use the FFmpeg path. **Use GPU decoding for high-resolution FFmpeg files** uses D3D11VA on Windows and VideoToolbox on macOS for supported clips above 1080p60 by resolution or pixel rate. The first picture can open in software while format detection runs. If hardware decoding fails, playback resumes in software. The FFmpeg path still delivers decoded pictures in system memory. On Windows, enable **DirectShow** to use installed filters for files outside the FFmpeg list. Choose an MPEG-2 or H.264 video filter and edit **Blocked Filter List**. LiveMix rejects a graph with a blocked connected filter before playback and tries FFmpeg. The audio track still uses FFmpeg. Reopen the input after changing decoder preferences.

Use **Import**, **Export** and **Default** in the Settings footer. Choose **Legacy XML settings (*.config)** in the Windows export dialog or use the `.config` suffix to exchange the supported legacy preferences. The import notice shows the count applied and skipped. Use JSON to transfer all LiveMix preferences. See the [modal and settings audit](AUDITORIA-MODAIS.md) for the format and scope. Stop recording and active outputs before importing or resetting. LiveMix exports a versioned JSON file with application settings, including device selections and paths. RTMP URLs and keys, and SRT passphrases and stream IDs are omitted. Re-enter those values after importing. Import and Default back up the previous settings to `settings.previous.txt` in the LiveMix storage folder. NDI and OMT senders stay disabled until manually enabled. Reopen existing media and restart LiveMix to apply any changed startup options.

**MultiCorder → Record original NDI video** uses the NDI Record utility for selected NDI inputs. It writes the source audio and uses the source format. MultiCorder codec, audio bus and split settings apply to the other inputs. Full-bandwidth NDI video is saved without recompression. The utility opens a separate network connection to the source. When the utility is unavailable, MultiCorder uses its regular encoder.

Enable **Save NDI as MKV after recording** to copy the original video and audio streams from MOV to MKV with FFmpeg when recording stops. The temporary MOV remains available if the streams cannot be copied. This mode needs free space for both containers during finalization and copies only the video and audio streams. MOV-specific metadata may be lost.

**MultiCorder → Record original OMT video** writes the original VMX1 video to MKV. It adds source PCM audio when **Audio track** is on. The mode uses the source format and timestamps, opens an additional OMT connection and bypasses the codec, audio-bus and automatic split settings. Use a version of FFmpeg that decodes VMX1 to play these files.

### Production clocks, physical audio and External Output

- In **Settings → Display**, configure the two production clocks. Use elapsed time, manual countdown, recording, streaming or Program time remaining. Right-click a visible clock to change its mode or message.
- In **Settings → Audio Outputs**, assign an independent stereo playback device to Master and each bus A–G. Select **Off** to close an output. Headphone solo stays on the headphone monitor.
- In **Settings → External Output**, leave the DeckLink mode on **Auto** to pick a renderer resolution and timing independently of the project source. An explicit device mode overrides these selections.
- In **Add Input → Blackmagic HyperDeck**, enter the deck IP and select its video capture device. Open the input's **General** settings and expand **Blackmagic HyperDeck** to see the transport state and active clip. List clips, play one clip or a consecutive range, and start or stop recording on the deck. Bring the video into the input via your capture connection. For a custom playlist, enter clip IDs in the desired order, separated by commas, then choose **Play playlist**. LiveMix waits for the deck to finish each clip before starting the next. **Stop playlist** stops playback. The IP and playlist are stored in LiveMix presets.

On Windows, **Settings → Decoders → DirectShow → Properties** opens the selected decoder's own property pages, when it provides them. Enable **Deinterlace Blend** on an interlaced input to blend pairs of lines in the DirectShow RGB path.

## Live timing tower

A GT title can show a timing tower fed by data. Open the title's **Input Settings → General → Live Timing**.

1. Build or generate a template whose rows are layers named `Row1`, `Row2`… with text fields `Row1.Pos`, `Row1.No`, `Row1.Name` and `Row1.Time`. `docs/examples/timing-tower/make_tower.py` writes one: `py make_tower.py tower.gtzip --rows 20`. Add `--header-image`, `--row-odd` and `--row-even` to use your own pictures, and `--no-colour` for the number colour. Other fields, such as `Header.Event`, `Header.Mode` and `Header.Class`, are optional.
2. Add the `.gtzip` with **Add Input → Title**. Turn **Live Timing → On** and enter a file path or an `http(s)` URL. LiveMix reads it every few seconds on its own thread. It accepts JSON and XML. A read that fails keeps the last good data on screen and shows the error.
3. Cars are the first array of objects in the data. **Mapping → Cars at** sets another path, such as `drivers`. Cars are ordered by **Order by** (default `position`). **Row fields** maps each field suffix to a key, one `Suffix=key` per line: `Name=fullname`. `{rank}` is the displayed position. **Other fields** maps fields outside the rows with absolute paths, such as `Header.Event=meta.eventname`. `@mode`, `@class` and `@rows` are available. XML elements like `<label type="eventname">` are reachable as `resultspage.label_by.eventname`.
4. **Show** chooses what the `Time` field displays: **Lap time**, **Gap to leader** or **Interval** to the car ahead. A gap the data lacks is computed from the total-time key (`total_ms`, milliseconds; a key without `ms` is read as seconds). The leader shows the **Leader shows** key in the gap modes. Shortcut: `SetTimingMode <input> lap|gap|interval|next`.
5. **Class** shows every car, one class, or **Rotate** through the classes every few seconds. Positions are counted inside the class. Shortcut: `SetTimingClass <input> all|rotate|<name>`.
6. With **Slide on position change**, each row stays with its car and moves between positions. Without it, rows keep their place and their text changes. Rows with no car are hidden.
7. Entrance and exit use the template's own storyboards plus the overlay effects. A changed field plays its template's `DataChange` animation; the generated template fades names and positions and updates times without animation.
8. For a camera inside the tower, put the camera and the tower title on the layers of another input (**Layers**), the camera first. The generated template leaves an empty `Cockpit.Frame` as a guide.

The `docs/examples/timing-tower` folder also has `timing-sample.json`, `timing-sample.xml` and `simulate-timing.ps1`, which rewrites a changing race to a file every second. A URL needs the server to answer within 8 seconds. Pages that need a login or custom headers are not supported.

## GT QR codes, masks and mirrored objects

- A `QRCode` object shows a QR code of the text of the field named like the object. Edit the text in **Title Editor**; the code is redrawn at once. It is black on white, with a margin of two modules, in the largest square that fits the object's area.
- The Skew effect leans pictures and text as well as shapes.
- A half turn about the X or Y axis, and the FlipX and FlipY effects, mirror shapes and pictures. Other 3D rotations, and mirrored text, are still reported as unsupported.
- A rectangle with the Cube geometry is drawn as the front face of a box of the depth in its dimensions, in its solid colour or picture, and spins when the title says so.
- A title can have pages (`Page1`, `Page2`…): extra animations that play once on request. Use **Play page** in **Title Editor**, or `TitleBeginAnimation <input> Page1`. A page plays like an entrance for the objects it lists; the original's rules for what a page leaves behind are not known, so the title returns to its resting state when the page ends.
- A Scroll animation moves the brush of an object one object size over its duration while the title enters, which is how the shimmer of a screen share title sweeps.
- An image whose resource lists several pictures cycles through them when the title says ImageSequenceLoop, one picture a second, an approximation. The sequence pictures are those saved with the title.
- 3D rotation about X or Y squashes an object by the cosine of the angle, and mirrors it past a quarter turn. Half turns are exact; other angles have no perspective, so the far side is not smaller.
- A mask limits an object to the area of the object it names. The area is the mask object's bounding box, so a mask that is not a rectangle, or whose object moves in an animation, is only approximated. A mask that names an object that is not in the title limits nothing and is listed as ignored.

## GT tickers

A GT title with a `Ticker` object shows a scrolling list inside the ticker's area. The list is the text of the field named like the ticker (`Ticker`, for example), shown in **Input Settings → General → Title Editor**. Write one item per line. `SetText <input> Ticker <text>` sets the whole field as a single line, so a shortcut can replace the list with one item; several items are written in the Title Editor. The items loop without stopping: a long list passes one item after another, a short one crosses the area and comes back.

- A ticker without a template draws each line as text in the ticker's font, size and colour, with a gap of two font sizes between items.
- A ticker with a template, such as the message card of `Social Ticker`, draws the template for each line. The parts of the line separated by `|` fill the template's text fields in the order they are drawn: `Ana|Hello` fills `FromName` and `Message`. A missing part keeps the template's sample text.
- The ticker travels to the left unless it says otherwise: `Direction` Right, Top (up) or Bottom (down). `Speed` is in template units per frame at 60 frames a second, an approximation of the original. Only the default `Add` type is supported; other types are reported.
- The position in the loop follows the clock of the application, not the moment the title goes on air.

## Checking a GT template

To see which GT Designer features a template uses that LiveMix does not support, run from a terminal:

```text
livemix.exe --gt-report "D:\Templates"
```

GT titles from vMix sometimes point at its texture library by an absolute path, such as `C:\Program Files (x86)\vMix\GT\textures\roof\Brown.jpg`. LiveMix looks for such a picture beside the title and under the `textures` folder of an installed vMix, or under the folder named by the `LIVEMIX_GT_TEXTURES` environment variable, using the part of the path after `textures`. It never opens other paths on the disk. A texture that is still missing is reported as `Missing or external bitmap`.

The path can be one `.gtzip` file or a folder, searched to a depth of twelve levels. Each file prints `OK`, `WARN` or `FAIL` with its size, field count and entrance and exit durations. An `approximate:` line lists features drawn only approximately, such as masks; they do not make a file a `WARN`. A `WARN` lists the unsupported features the reader reports, such as `Mask`, `Transform`, `Effect Glow`, `Crop feather`, unknown object types and unknown animations, and an `ignored` line with attributes and properties it does not read, such as `TextBlock.LineSpacing attribute`. A summary at the end counts the files that use each one. The exit code is 0 after a scan and 2 when the path is missing or has no `.gtzip` files.

An empty list means the reader found nothing it knows to be missing, not that the picture matches GT Designer. A feature the reader has never heard of can still be dropped without a notice, so compare an important template with its original.

## Replay and Telestrator

For OMT angles recorded in original VMX1, Play can prepare an event from the active file once frames past the Out Point are available. For H.264 or HEVC angles, enable **Replay → Setup → Play MP4 while recording (FFmpeg)** before recording. LiveMix writes fragmented MP4 and waits for FFprobe to see published frames through the Out Point. The recording continues while FFmpeg prepares playback. Older MP4 segments and recordings made with this option off keep the existing finalization behavior.

Replay uses software encoding by default. **Replay → Setup → Use hardware encoder for Replay** enables hardware encoding separately for this session. If an encoded angle reports a recording error while this option is active, Replay continues with software encoding and retains the valid segments.

On Windows, native H.264 Replay angles that match the project size can use a smaller NV12 transfer from the GPU. The capture falls back to BGRA on incompatible routes or when the encoder rejects NV12. Fragmented MP4 recording through FFmpeg uses the existing BGRA path.

**Replay → Setup → Record cameras from capture** encodes camera angles from the source's capture thread instead of drawing them in the Program renderer and reading them back from the GPU. Use it to record many cameras, up to eight, without tying the recording to the interface frame rate. It applies to camera, capture card, NDI, OMT and SRT inputs. Program and other input types are still rendered. Each camera is recorded as captured, without the input's colour, crop or layer settings. A camera faster than the replay frame rate loses its surplus pictures. On Windows, a camera that matches the replay size is converted to NV12 once and is not converted again by the encoder. These inputs switch to system-memory frames while they are recorded. If a camera sends no picture within two seconds, its angle is rendered for the rest of the recording and the controller reports the fallback. The option is off by default and in older sessions.

Media Foundation replay segments place a keyframe every half second and use no B-frames, so cueing, jog and reverse decode fewer frames. Reverse and backward jog reuse the pictures already decoded on the way to an earlier frame.

Enable **Resume playback when speed rises above 0%** to resume indexed playback after pausing it with the speed fader.

1. Use **Add Input → Instant Replay** to create **Replay A** and **Replay B**. In **Replay → Setup**, select a session folder, assign up to eight cameras and configure format, audio and rolling storage. Choose **New Session** for an empty folder or **Open Session** to recover a LiveMix session.
   In **Configure Storage**, choose an existing folder for each camera you want to move to another disk. Leave a field blank to use the session disk. LiveMix creates a **LiveMix Replay** subfolder for the media and stores the index in the session folder. Destination changes apply to new segments. If a destination is unavailable at the start of a segment, LiveMix uses the session disk and reports the fallback in the controller.

   Enable **Record original OMT video** with **Follow camera** to record OMT angles as VMX1 MKV. Other angles use the selected Replay encoder. LiveMix keeps the source-derived timing in the camera index and uses FFmpeg for playback and export.

2. Use the compact strip beside **Replay A** to record, mark the last 5 or 10 seconds, play the latest event to Program, adjust A's speed or open Setup. In the Replay controller, **IN Mark / OUT Mark** and the quick marks **-5**, **-10**, **-15** and **-20** are available. A quick mark selects the new highlight and cues the selected player on its In Point, paused, ready for **Play** or **Take**. While recording live it waits for the open segment to close, which can take a few seconds. Marking references the session timeline and leaves recording active. Mark Out adds and selects the event immediately. At 100% speed, an individual LiveMix replay channel plays directly from recorded segments. If the start or end is still being written, Play requests early finalization of that segment and recording continues in a new segment. Slow motion, linked A/B and native imports may still need preparation. With retention enabled, segments outside the rolling window are removed if no saved or pending event references them.
3. Select an event, choose **A**, **B** or **AB**, and choose cameras and speeds. **Play** cues Preview and **Play to Program** takes the selected channel to Program. In AB mode both channels are prepared before playback and A takes Program. **Pause / Resume** controls the selected channel or pair. Speed changes apply the next time you press **Play**.
4. In **Replay → Setup → Replay preview options**, enable **Show live sources in Replay A and B in Live mode** to see the assigned inputs in the Replay monitors, input tiles and MultiView. Use **Recorded** to show replay footage. Playing an event switches the monitors to the recorded image. The Replay controller shows players A and B beside the camera grid. Click a camera to assign it to the selected player, or right-click to assign it to B. **Undock** moves the controller to its own window, the gear opens Setup, **MONITOR** hides the pictures and **LIVE** switches between live sources and recorded footage. Each highlight belongs to one of four **EVENTS** lists and has one cell per camera: click the square to mark the angle as Selected (red), right-click it for Favourite (cyan), click the name to select it and double-click to cue it on the selected player at its In Point. Drag an In or Out Point sideways for coarse changes and use the mouse wheel for single frames. **Shift** goes to the In or Out Point of the selected highlight; jog to another frame and press **Mark** to move that point. Click a tag to add or remove it on the selected angle, double-click a tag to rename it, and use **Clear** or **Edit** for the comment. **Play Selected** plays the Selected angles of the current list in time order. **Add** and **Insert** copy the selected angle into one of eight playlists, where each clip keeps its own In/Out, speed and mix; **PL** plays the current playlist on that player, and a clip with a mix starts on the other player so Program can mix between A and B. **Preview Mode** keeps cue, camera buttons and jog on the off-air player while the speed control follows the one on Program; **Take** plays the cued player to Program. Music beds and imported clips are not available yet. Set A and B playback speed independently from 0% to 100%. A value of 0% pauses that channel. Other values apply at the next playback. Use **Recorded position** to seek within the selected camera’s retained recording, then use the frame buttons to fine-tune IN and OUT. The transport controls also offer reverse, pause/resume and access to the live buffer. **Live buffer** plays the latest finalized camera segment directly and follows new segments as they close. **−1 frame** and **+1 frame** seek through the selected channel's indexed recording. **Reverse** seeks backward through that recording and runs without audio. These controls use finalized segments, so live playback trails the current write.
5. **Open Session** also accepts a legacy session folder with `replay.xml` or `replay2.xml`. LiveMix opens it read-only, lists its events, and prepares supported camera media with FFmpeg. If the recording uses separate MPEG `.vdata` and `.adata` tracks, use **Play** or **Export** to prepare them. Derived files for imported sessions are stored under **Imported Replay** in the LiveMix storage directory.
6. **Export** writes an MP4 into a LiveMix session's `export/` folder. The session saves event IDs, time ranges, available angles, descriptions and event speeds in `livemix-replay.json`. FFmpeg prepares clips for playback and export. Keep the manifest and original camera segments together.

Add a **Telestrator** input and assign it to an overlay. Draw freehand in its input settings or start **Settings → Web Controller** and open `http://127.0.0.1:8088/telestrator/` on the LiveMix machine. The browser sends its strokes to the first Telestrator input. Use the editor's undo or clear controls during the show.

## Timing tower

A **GT Title** can show live timing as a timing tower. LiveMix reads a JSON or XML file or an `http`/`https` URL on a background thread and writes the cars into the title's text fields. Changed fields play the template's own data-change animations, and the entrance and exit are the template's **TransitionIn** and **TransitionOut**.

1. **Template.** Name the rows `Row1` to `RowN` (a Layer each) and their fields `Row1.Pos`, `Row1.No`, `Row1.Name`, `Row1.Time` and so on. Other fields such as `Header.Event`, `Header.Mode` and `Header.Class` are filled from the data too. `docs/examples/timing-tower/make_tower.py` builds a complete template without GT Designer: `py make_tower.py tower.gtzip --rows 20`. It accepts a header picture and row pictures (`--header-image`, `--row-odd`, `--row-even`), the font, the colours and the row geometry. `timing-tower.gtzip` in the same folder is a ready example with `timing-sample.json` and `timing-sample.xml`.
2. **Input.** Add the template with **Add Input → Title**. In **Input Settings → General → Live Timing**, switch **On**, enter the **File or URL** and how often to **Read**. The status line shows the cars read, the rows shown and the age of the last read. A read that fails, such as a half-written file or a server error, keeps the last good data on screen and shows the reason.
3. **Show.** Choose **Lap time**, **Gap to leader** or **Interval**. In the gap and interval modes the leader shows its total time. A gap or interval the data lacks is computed from the **Total time (ms) key**; times given as numbers are milliseconds when the key ends in `ms` and seconds otherwise. **Class** shows every car, one class, or **Rotate** to cycle the classes every few seconds. The shortcut commands `SetTimingMode <input> lap|gap|interval|next` and `SetTimingClass <input> all|rotate|<class>` switch them live.
4. **Rows.** With **Slide on position change**, each row stays with its car and moves to its new position over the chosen time. Without it, the rows keep their place and their text changes. Rows without a car are hidden. Rows are found by name and spaced by the distance between `Row1` and `Row2`.
5. **Mapping.** The defaults read the layout of `data.json` (`drivers`, `position`, `no`, `fullname`, `class`, `lasttime`, `gap`, `total_ms`). Under **Mapping**, **Cars at** is the path to the array of cars (empty finds the first array of objects), **Order by** the key that ranks them and **Car identity** the key that follows a car between reads. **Row fields** lines are `Suffix=key`, where `{rank}`, `{mode}`, `{lap}`, `{gap}` and `{interval}` can be used as keys. **Other fields** lines are `Field=path` with dots between levels, plus `@mode`, `@class` and `@rows`. XML attributes and child elements are keys, repeated elements are arrays, and a labelled value such as `<label type="eventname">Race</label>` is read as `label_by.eventname`.
6. **Second camera.** The title only draws the tower. Put a camera behind it with **Input Settings → Layers**: on a base input, set a layer to the camera with a position, crop and border over the template's **Cockpit.Frame**, and a later layer to the tower. Send that input to Program or to an overlay for the overlay effect and duration.

`docs/examples/timing-tower/simulate-timing.ps1` writes a race that changes every second, to try the tower without a timing system.

## Cameras and capture cards

Choose **Add Input → Camera** and pick the device. For webcams, USB cameras and capture cards, LiveMix reads the modes the device reports and lists **Resolution**, **Frame Rate** (interlaced modes are marked) and **Video Format**. **Auto** takes the best mode up to the Performance limit. Capture cards usually send audio on a separate Windows audio input, so choose it in **Audio Device**; LiveMix selects an input whose name matches the card when it finds one, and **None** leaves the picture without audio. The same options are in **Input Settings → General**, and a new choice restarts the camera. Blackmagic DeckLink devices use their own connector and video format list. On macOS the mode list is not available and the camera stays on **Auto**.

### Sony PXW-Z200

1. In LiveMix, choose **Add Input → Sony Camera / SRT**. Use a different UDP port for each camera. The default starts at **9000**.
2. In the camera's streaming destination, choose **SRT**. Enter the computer's LAN IP and the UDP port shown in LiveMix. The camera is the Caller. If you use encryption, enter the same passphrase and AES strength on both ends. Start streaming from the camera. [Sony streaming guide](https://helpguide.sony.net/pro/z200nx800/v1/en/contents/stream_stream.html)
3. For controls, set **Network → Wired LAN → Remote** to **Enable** on the camera and start the local **Alpha Camera REST API** bridge built against the Sony Camera Remote SDK. In the input's **General → Sony Camera Remote** panel, discover the camera and choose its ID. Connect, then read and apply the values the camera advertises. Enter the camera credentials and the SDK fingerprint from the bridge's documented fingerprint endpoint if authentication is required. The input remembers only the camera ID for remote control. [Sony network setup](https://helpguide.sony.net/pro/z200nx800/v1/en/contents/network_lan.html) · [Bridge setup](https://crsdk.github.io/alpha-sdk-api/web-api/server/)
4. Select the Sony input as **Target** in Camera Match and choose **Apply to Sony camera** to request a supported shutter speed and white-balance temperature. The result reports each control independently. Available controls depend on the camera model, firmware, and camera mode. Confirm them on the camera before using them on air.

### Camera Match

Open **Camera Match** from the top bar to make two cameras look alike. Choose a **Reference** input and a **Target** input, enter the settings you know for each camera (white balance in kelvin, ISO, shutter and iris; leave a field at "—" when unknown) and point both cameras at the same scene or chart. LiveMix measures the highlighted rectangle of each preview (the centre half until you change it). Drag on a preview to choose another rectangle, for example so both cameras measure the same wall or the same person; double-click to reset it. LiveMix lists what to change on the target camera: exposure (shutter first, then iris, then ISO, in third-stop steps), white balance, tint, contrast and saturation. Green entries already match. Measurements ignore clipped and crushed pixels, so avoid scenes dominated by pure white or black.

**Match target** adjusts the target input's Colour Correction in small steps until the colour difference (ΔE) is below 1. The cameras themselves are not changed, and **Undo** restores the previous Colour Correction. On Windows, **Apply exposure and white balance to USB camera** requests the measured correction directly from the active UVC capture driver. The driver must expose manual exposure or white balance controls. The result appears in Camera Match and the input status.

## Teleprompter

Use **Add Input → Teleprompter**, paste the script or choose **Load text file…** (UTF-8, UTF-16 or Windows text, up to 4 MB), and press OK. **Import text file…** in Input Settings replaces the script of an existing input and returns to the first line. Press play on the input tile to scroll; the bar under the picture seeks by line. In **Input Settings → Teleprompter** set the speed in lines per minute, text size, line spacing, margins, alignment, colours and the highlighted reading line, and turn on **Mirror** or **Flip** for a prompter glass. **Loop at the end** restarts the script; otherwise scrolling stops on the last line. To show the script only to the presenter, choose the input as the source of an external output window. The scroll length comes from the picture the last time it was drawn, so a script that has never been visible does not stop at its end.

Under **Input Settings → Teleprompter → Audio to follow**, choose the presenter’s microphone or another input with audio. Press **Play** to arm scrolling. The prompter advances at the selected speed while the audio exceeds the **Speech threshold** (−36 dBFS by default). It holds for 450 ms by default before pausing, and starts again when audio returns. Adjust both controls while watching **Audio level**. The detector uses the level before the input fader and mute, so the mic can drive the prompter without going to Program. **Pause** and manual seeking still work. If the source disappears, scrolling waits for a new source. Choose **None** for continuous scrolling.

To control the scroll during the show, press **Settings → Shortcuts → Add Teleprompter keys**: **Space** plays or pauses, **Up** and **Down** scroll three lines, **Right** and **Left** change the speed by 5 lines per minute, **Home** returns to the top, and **+** and **−** change the text size. Keys that are already bound are skipped, and you can rebind any of them. The commands also work from MIDI and automation scripts: `TeleprompterPlayPause`, `TeleprompterFaster [step]`, `TeleprompterSlower [step]`, `TeleprompterSpeed <lines/min>`, `TeleprompterScroll <lines>` (negative goes back), `TeleprompterHome`, `TeleprompterEnd`, `TeleprompterBigger`, `TeleprompterSmaller`, `TeleprompterFlipSides`, `TeleprompterFlipVertical` and `TeleprompterLoop`. They act on the Teleprompter on Output, or the first one, and do nothing when there is none. With several, give the input number first, for example `TeleprompterSpeed 3 40`. For a MIDI knob use `TeleprompterSpeed {value}`.

## Control and automation

- **Settings → Shortcuts** edits keyboard and MIDI bindings. Select the MIDI input devices, enable MIDI, add a shortcut and enter an action from **Available commands**. Click **Learn key** or **Learn MIDI**, then press a key or move a controller. **Esc** cancels learning. **Match value** restricts a MIDI binding to one value. Continuous CC commands can use `{value}` (0–100) or `{delta}` (signed relative value). For a relative replay wheel, use `ReplayStep {delta}`. Commands use input numbers or `@ID` when a stable LiveMix input ID is known.
- Paste a shortcut template file's XML in **Import template XML**. Import reports skipped rows, including unavailable functions, unsupported mixes and foreign input GUIDs. The searchable reference lists all function names found in the inspected version.
- **Settings → Activators** sends MIDI Note On or CC messages to a selected output on changes in Program, Preview, recording, streaming, MultiCorder, replay recording, overlay and fade-to-black state. Configure the channel, note or controller, and the active and inactive values. Use separate routes when a virtual MIDI port echoes output into input.
- **Settings → Options → Interface language** switches between English and Brazilian Portuguese and saves the selection.
- **Settings → Web Controller** starts the browser switcher at `http://127.0.0.1:8088/` on the LiveMix machine. It lists inputs, shows Program, Preview, recording and streaming status, and supports Preview, Cut, Fade and toggling assigned overlays.
- **Settings → Scripting** runs sequences of LiveMix commands. Enter one command per line, such as `Preview 2`, `Wait 1000`, `Fade 500` and `Cut`. Wait and Fade durations are in milliseconds.
- **Input Settings → Triggers** runs commands when that input goes to Program. **Input Settings → PTZ** accepts the camera's IP and exposes pan, tilt, zoom, home and presets for supported VISCA devices.

## Diagnosing slow frames

To find out why the interface hitches, start LiveMix with the environment variable `LIVEMIX_SLOW_FRAMES=1`, or a threshold in milliseconds such as `LIVEMIX_SLOW_FRAMES=60`. Every update slower than the threshold, and every update that starts more than 250 ms after the previous one ended, appends a line to `slow-frames.log` in the LiveMix storage folder (next to `settings.txt`). The line shows the time, frame number, window size (marked `RESIZED` after a size change), the gap before the update, the total update time and the milliseconds spent in each phase (`media`, `monitors`, `dialogs`, `finish` and so on). Phases under 1 ms are left out, and a large `gap` with a short update means the time was spent outside LiveMix's update, such as in the window system or the GPU driver. The log is off by default and stops growing at 5 MB.

See [setup](SETUP.md) for the runtimes and permissions used by each route.
