# Operator guide

1. Open **Add Input** and add a camera, clip, graphic or network source. Click a card to prepare it in **Preview**. Use **Cut**, a transition or the T-bar to send it to **Program**.
2. Configure layers, positioning, picture and sound in **Input Settings**. Assign an input to one of the eight overlays when it should appear above the video.
3. Choose the source for each output in **Settings → Outputs / NDI / OMT / SRT**. Set the corresponding destination or hardware connector before enabling it.
4. Save the show as a `.livemix` project preset. To open an older XML preset in Windows, select **All files** in the Open dialog. Use **Save As** to save it with the new extension. Reopening it shows an import report with unsupported inputs and missing asset references. Keep the media files accessible from the machine that opens the show.

**Last** restores the automatic recovery preset in the LiveMix storage directory. LiveMix writes this copy roughly every 60 seconds and before **New** or a normal exit. The untouched startup demo and empty projects are skipped. Use **Save As** after restoring to create an ordinary project file.

## Display and source selection

In **Settings → Display**, set the theme and the Preview and Output colors. The colors also apply to the matching input and MultiView title bars. Set the monitor, source and overlay option separately for **Fullscreen 1** and **Fullscreen 2**. Open them from the top toolbar. Active outputs use separate monitors. Click the Production Clock under the overlay buttons to pause or resume, and right-click to reset.

Use **Add Input → Audio** for an audio-only file. **Recent media** remembers the last successfully added video, image, audio files and photo folders. In **Settings → Performance**, turn NDI/OMT thumbnails on or off. The browser requests a single frame per source and keeps source selection available while previews load.

Use **Add Input → Web Browser** for an HTTP or HTTPS page. Under **Input Settings → General**, change or reopen its URL and enable **Transparent** to preserve alpha from a page with a transparent background. Chromium renders at 1280×720. LiveMix requests up to 15 pictures per second for on-air or monitored sources and two per second for other cards. Browser capture is video only.

On camera, video, image and other picture inputs, use **Input Settings → Colour Correction → 3D LUT** to browse for a .cube or tiled PNG LUT. Supported cubes have 2–65 samples per axis. For PNG, use a strip or grid of square blue slices with red across each tile and green down it, such as a 512×512 8×8 grid. The project keeps the LUT path, so keep the file accessible when moving a preset. Use **Colour Key → Luma Key** to remove dark pixels, adjust **Threshold** and **Softness**, or enable **Remove bright pixels** to invert the key. Use a keyed input as an overlay or layer to reveal the background.

Use **Add Input → PowerPoint** to open a presentation. Wait for conversion, then use the previous and next buttons on the input card or in **Input Settings → General**. Save the original deck alongside the project. Slides render as stills.

Use **Add Input → Virtual Set** and open **Input Settings → Layers**. Assign a backdrop to layer 1, presenter inputs to layers 2 and 3 and a desk or foreground to layer 4. Enable chroma key on the presenter inputs when needed. Choose **Wide**, **Left** or **Right** under **General → Camera**.

In **Streaming Settings**, choose one of five slots, then select its source, resolution, bitrate and codec. Destinations with matching source, audio, resolution, bitrate and codec share one RTMP encoder. Starting or stopping a member can restart that group. HEVC over RTMP/RTMPS requires a compatible FFmpeg build and receiver. [YouTube Live encoder settings](https://support.google.com/youtube/answer/2853702)

## Audio, recording and streaming

Add a microphone or interface with **Add Input → Audio Input**. In **Audio Mixer**, use **HP** and the adjacent selector to monitor Master, A or B through the system output. Drag the round knob vertically to change headphone volume. Double-click to reset it to 100%. Use **i** on the Master strip to inspect Audio Engine statistics. Click **OUTPUTS** or **INPUTS** to collapse a group, and use a channel gear to open its audio settings. Right-click the mixer title to make the input strips follow the selected input category. **Input Settings → Audio → Audio Settings** opens the same per-input dialog as the mixer gear. It provides channel selection, gain and delay under General, with separate pages for EQ, compression and noise gate. On each input strip, use **M**, **A** and **B** to assign buses and the speaker button to mute. **S** isolates the selected inputs in headphone monitoring. Right-click **S** for pre-fader Solo, which ignores the input fader and mute. The automatic mixing button follows Program with a crossfade on timed transitions and preserves mute and bus assignments. Each input card with audio has a stereo meter. In **Settings → Display → MultiView**, enable **Program audio meter** or **Input audio meters** for each layout. Program and MultiView routes use the Master mix. Preview and per-input routes take the corresponding input audio.

Use the Record gear to configure Recording 1 and Recording 2. Each slot has a video source, codec and **Audio track** toggle. Composed outputs record the stereo Program mix. MultiCorder uses the same codec choices and can record each selected source separately. Camera files use their source audio when available. Both recording slots share the destination folder and split interval.

| Container | Video profiles | Stereo audio |
| --- | --- | --- |
| MP4 and MKV | H.264, HEVC | AAC |
| AVI | MJPEG, MagicYUV | PCM |
| MPEG-2 TS and PS | MPEG-2 | MP2 |
| WMV | WMV8, WMV9 on Windows | WMA2 |
| MOV and MXF | ProRes 422 (MOV), DNxHR HQ | PCM |

Open the Stream gear for RTMP/RTMPS destinations. Each slot defaults to the **Master mix**, with **Selected video source** available for isolated audio. YouTube uses stereo AAC at 44.1 kHz and 128 kbps. Open **Streaming log** to inspect encoded video progress, input audio peak and sample counts, and FFmpeg messages. **Copy log** copies the recent lines with destination URLs and credentials removed. SRT output settings show the same diagnostics. Destinations with matching encoding and audio settings can share an encoder. Changing group membership restarts that encoder.

The Preview waveform, RGB parade and vectorscope use OpenGL when available. **Settings → Performance** reports the active scope path. Waveform and parade textures are 1200×256 and the vectorscope is 512×512. The LiveMix scopes sample the composed Preview at 640×360. On Windows, compatible D3D11 file playback applies chroma key and colour correction in OpenGL. Inputs supplying a Video Delay buffer still use system-memory pictures.

In **Settings → Decoders**, choose FFmpeg for specific file extensions or all video files on Windows. Other files first try Media Foundation, with FFmpeg as a fallback when it cannot deliver the first picture. macOS uses FFmpeg for video files. **BWDIF** and **YADIF** deinterlace frames marked as interlaced on the FFmpeg path. Changes apply the next time a video or playlist reader opens. See **Input Settings → General → Decoder** for the active path. FFmpeg and FFprobe must be available to use the FFmpeg path. **Use GPU decoding for high-resolution FFmpeg files** uses D3D11VA on Windows and VideoToolbox on macOS for supported clips above 1080p60 by resolution or pixel rate. The first picture can open in software while format detection runs. If hardware decoding fails, playback resumes in software. The FFmpeg path still delivers decoded pictures in system memory. On Windows, enable **DirectShow** to use installed filters for files outside the FFmpeg list. Choose an MPEG-2 or H.264 video filter and edit **Blocked Filter List**. LiveMix rejects a graph with a blocked connected filter before playback and tries FFmpeg. The audio track still uses FFmpeg. Reopen the input after changing decoder preferences.

Use **Import**, **Export** and **Default** in the Settings footer. Choose **Legacy XML settings (*.config)** in the Windows export dialog or use the `.config` suffix to exchange the supported legacy preferences. The import notice shows the count applied and skipped. Use JSON to transfer all LiveMix preferences. See the [modal and settings audit](AUDITORIA-MODAIS.md) for the format and scope. Stop recording and active outputs before importing or resetting. LiveMix exports a versioned JSON file with application settings, including device selections and paths. RTMP URLs and keys, and SRT passphrases and stream IDs are omitted. Re-enter those values after importing. Import and Default back up the previous settings to `settings.previous.txt` in the LiveMix storage folder. NDI and OMT senders stay disabled until manually enabled. Reopen existing media and restart LiveMix to apply any changed startup options.

## Replay and Telestrator

1. Use **Add Input → Instant Replay** to create **Replay A** and **Replay B**. In **Replay → Setup**, select a session folder, assign up to eight cameras and configure format, audio and rolling storage. Choose **New Session** for an empty folder or **Open Session** to recover a LiveMix session.
2. Use the compact strip beside **Replay A** to record, mark the last 5 or 10 seconds, play the latest event to Program, adjust A's speed or open Setup. In the Replay controller, **IN Mark / OUT Mark** and the quick marks **-5**, **-10**, **-15** and **-20** are available. Marking references the session timeline and leaves recording active. Mark Out adds and selects the event immediately. At 100% speed, an individual LiveMix replay channel plays directly from recorded segments. If the start or end is still being written, Play requests early finalization of that segment and recording continues in a new segment. Slow motion, linked A/B and native imports may still need preparation. With retention enabled, segments outside the rolling window are removed if no saved or pending event references them.
3. Select an event, choose **A**, **B** or **AB**, and choose cameras and speeds. **Play** cues Preview and **Play to Program** takes the selected channel to Program. In AB mode both channels are prepared before playback and A takes Program. **Pause / Resume** controls the selected channel or pair. Speed changes apply the next time you press **Play**.
4. In **Replay → Setup → Replay preview options**, enable **Show live sources in Replay A and B in Live mode** to see the assigned inputs in the Replay monitors, input tiles and MultiView. Use **Recorded** to show replay footage. Playing an event switches the monitors to the recorded image. The Replay controller shows players A and B beside the camera grid. Click a camera to assign it to the selected player, or right-click to assign it to B. **Undock** moves the controller to its own window, the gear opens Setup, **MONITOR** hides the pictures and **LIVE** switches between live sources and recorded footage. Each highlight belongs to one of four **EVENTS** lists and has one cell per camera: click the square to mark the angle as Selected (red), right-click it for Favourite (cyan), click the name to select it and double-click to cue it on the selected player at its In Point. Drag an In or Out Point sideways for coarse changes and use the mouse wheel for single frames. **Shift** goes to the In or Out Point of the selected highlight; jog to another frame and press **Mark** to move that point. Click a tag to add or remove it on the selected angle, double-click a tag to rename it, and use **Clear** or **Edit** for the comment. **Play Selected** plays the Selected angles of the current list in time order. **Add** and **Insert** copy the selected angle into one of eight playlists, where each clip keeps its own In/Out, speed and mix; **PL** plays the current playlist on that player, and a clip with a mix starts on the other player so Program can mix between A and B. **Preview Mode** keeps cue, camera buttons and jog on the off-air player while the speed control follows the one on Program; **Take** plays the cued player to Program. Music beds and imported clips are not available yet. Set A and B playback speed independently from 0% to 100%. A value of 0% pauses that channel. Other values apply at the next playback. Use **Recorded position** to seek within the selected camera’s retained recording, then use the frame buttons to fine-tune IN and OUT. The transport controls also offer reverse, pause/resume and access to the live buffer. **Live buffer** plays the latest finalized camera segment directly and follows new segments as they close. **−1 frame** and **+1 frame** seek through the selected channel's indexed recording. **Reverse** seeks backward through that recording and runs without audio. These controls use finalized segments, so live playback trails the current write.
5. **Open Session** also accepts a legacy session folder with `replay.xml` or `replay2.xml`. LiveMix opens it read-only, lists its events, and prepares supported camera media with FFmpeg. If the recording uses separate MPEG `.vdata` and `.adata` tracks, use **Play** or **Export** to prepare them. Derived files for imported sessions are stored under **Imported Replay** in the LiveMix storage directory.
6. **Export** writes an MP4 into a LiveMix session's `export/` folder. The session saves event IDs, time ranges, available angles, descriptions and event speeds in `livemix-replay.json`. FFmpeg prepares clips for playback and export. Keep the manifest and original camera segments together.

Add a **Telestrator** input and assign it to an overlay. Draw freehand in its input settings or start **Settings → Web Controller** and open `http://127.0.0.1:8088/telestrator/` on the LiveMix machine. The browser sends its strokes to the first Telestrator input. Use the editor's undo or clear controls during the show.

## Control and automation

- **Settings → Shortcuts** edits keyboard and MIDI bindings. Select the MIDI input devices, enable MIDI, add a shortcut and enter an action from **Available commands**. Click **Learn key** or **Learn MIDI**, then press a key or move a controller. **Esc** cancels learning. **Match value** restricts a MIDI binding to one value. Continuous CC commands can use `{value}` (0–100) or `{delta}` (signed relative value). For a relative replay wheel, use `ReplayStep {delta}`. Commands use input numbers or `@ID` when a stable LiveMix input ID is known.
- Paste a shortcut template file's XML in **Import template XML**. Import reports skipped rows, including unavailable functions, unsupported mixes and foreign input GUIDs. The searchable reference lists all function names found in the inspected version.
- **Settings → Activators** sends MIDI Note On or CC messages to a selected output on changes in Program, Preview, recording, streaming, MultiCorder, replay recording, overlay and fade-to-black state. Configure the channel, note or controller, and the active and inactive values. Use separate routes when a virtual MIDI port echoes output into input.
- **Settings → Options → Interface language** switches between English and Brazilian Portuguese and saves the selection.
- **Settings → Web Controller** starts the browser switcher at `http://127.0.0.1:8088/` on the LiveMix machine. It lists inputs, shows Program, Preview, recording and streaming status, and supports Preview, Cut, Fade and toggling assigned overlays.
- **Settings → Scripting** runs sequences of LiveMix commands. Enter one command per line, such as `Preview 2`, `Wait 1000`, `Fade 500` and `Cut`. Wait and Fade durations are in milliseconds.
- **Input Settings → Triggers** runs commands when that input goes to Program. **Input Settings → PTZ** accepts the camera's IP and exposes pan, tilt, zoom, home and presets for supported VISCA devices.

See [setup](SETUP.md) for the runtimes and permissions used by each route.
